# อัปเดต backend: ชำระ POS ด้วยเงินสดร่วมกับเงินโอน

เพิ่มวิธีชำระ `MIXED` และ `PosSale.transferSatang` เพื่อเก็บส่วนที่โอน สำหรับบิลผสม `receivedSatang` เป็นเงินสดที่รับรวมกับเงินโอน และ `changeSatang` เป็นยอดรับรวมลบยอดบิล รายงานรายวัน/ปิดกะแยกเงินสดสุทธิหลังทอนและเงินโอน บิลเงินสด/โอนเดิมยังทำงานตามเดิม

ต้องลง migration `202611180001_pos_mixed_payment` ก่อนเริ่ม backend รุ่นนี้ แล้วจึงอัปเดตแอป POS ไม่ต้องเพิ่มตัวแปร `.env` ชุดนี้ไม่เปลี่ยนข้อมูลบิลเก่า

บน server ให้สำรองฐานข้อมูลก่อน (เปลี่ยนชื่อฐานข้อมูล/path/PM2 หาก deployment ของร้านต่างจากนี้):

```bash
mkdir -p ~/backups && chmod 700 ~/backups &&
sudo -u postgres pg_dump -Fc sian_member > ~/backups/sian_member_$(date +%Y%m%d_%H%M%S).dump
```

ตรวจว่า backup สำเร็จ จากนั้นตรวจงานค้างก่อน pull หากมีงานค้างให้เก็บงานก่อน ห้าม reset ทับ:

```bash
cd ~/8-sian-member-backend
git status --short
git pull --ff-only origin main
git log -1 --oneline
```

ช่วงบำรุงรักษา:

```bash
pm2 stop 8sian-backend &&
npm ci &&
npm run generate &&
npm run migrate &&
pm2 restart 8sian-backend --update-env
```

ถ้าขั้นใดผิดพลาดให้หยุดและแก้ก่อนทำต่อ ห้ามใช้ `migrate reset` ตรวจผล:

```bash
npx prisma migrate status
curl --fail-with-body http://127.0.0.1:3001/api/health
curl --fail-with-body https://api.8sianracha.com/api/health
pm2 logs 8sian-backend --lines 50 --nostream
pm2 status
pm2 save
```

Health ต้องตอบ `{"status":"ok"}` และ migration ไม่มีรายการค้าง ทดสอบบิล 1,000 บาท โอน 600 รับสด 500: ทอน 100, รายงานเงินสดสุทธิ 400, เงินโอน 600

## แดชบอร์ดและรายการบิล (25 พฤศจิกายน 2026)

Frontend เพิ่มเมนูแอดมิน “แดชบอร์ดยอดขาย” และ “รายการบิล” แดชบอร์ดใช้ API ใหม่ `GET /api/admin/pos/dashboard?from=YYYY-MM-DD&to=YYYY-MM-DD` ซึ่งคำนวณจากทุกบิลชำระแล้วในช่วงวันที่ ไม่จำกัดเฉพาะหน้าแรกของรายการบิล แสดงยอดสุทธิ เงินสด/โอน จำนวนบิล ยอดเฉลี่ย จำนวนสินค้า รายวัน และยอดสินค้าก่อนส่วนลดคูปอง โดยแยกชื่อ/ราคาสินค้าตามประวัติการขาย

ต้อง deploy backend และ frontend รุ่นที่มีการเปลี่ยนแปลงนี้ร่วมกัน ไม่มี schema หรือ migration เพิ่มจากการเปลี่ยนแปลงแดชบอร์ด รายการบิลใช้ API เดิมพร้อมตัวกรองวัน วิธีชำระ เลขบิล และแบ่งหน้าครั้งละ 20 บิล ทุก API ยังคงใช้ session ADMIN เดิม

## POS 0.6.26: session และตรวจบิลค้าง

Deploy backend ก่อนติดตั้ง APK 0.6.26 ด้วยขั้นตอนสำรองฐานข้อมูล, pull, ติดตั้ง dependencies, generate, migrate และ restart ตามด้านบน ไม่มี schema ใหม่สำหรับ recovery ใช้ AuditLog เดิมบันทึกการยกเลิกคำขอที่ยังไม่สำเร็จ

Session POS ใหม่มีอายุ 24 ชั่วโมง ส่วน session ที่สร้างก่อน deploy คงเวลาเดิม ต้องเข้าสู่ระบบใหม่เพื่อรับอายุใหม่ Login และ `/api/pos/me` ส่ง `expiresAt` ให้หน้า POS ใช้กลับหน้า login เมื่อครบเวลา การปิดบัญชีพนักงานและ logout ยังยกเลิกสิทธิ์ได้ตามเดิม

`POST /api/pos/checkout/recover` รับ `{ key, shiftId, action: 'CHECK' | 'CANCEL' }` จาก USER ที่เข้าสู่ระบบ ตรวจบิลของบัญชีเดิมเท่านั้นสำหรับบิลที่สำเร็จแล้ว CANCEL ไม่ลบ PosSale: หากบันทึกแล้วคืน PAID พร้อมบิลเดิม หากยังไม่สำเร็จจะล็อกกะ, บันทึก POS_PAYMENT_CANCELLED และปล่อยคูปองที่จองไว้ Checkout ตรวจ audit นี้ภายใน transaction เพื่อป้องกันรับชำระหลังยกเลิก หาก concurrent transaction ขัดกันคืน 409 ให้ตรวจผลอีกครั้ง

อย่า rollback backend ไปเป็นรุ่นที่ไม่ตรวจ POS_PAYMENT_CANCELLED หลังเริ่มใช้การยกเลิกคำขอแล้ว เพราะอาจทำให้คำขอเก่าที่ถูกยกเลิกสามารถยืนยันซ้ำได้
