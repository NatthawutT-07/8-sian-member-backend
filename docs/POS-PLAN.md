# 8 เซียน POS — แผนพัฒนาทีละขั้น

โฟลเดอร์นี้สำหรับระบบคิดเงินที่จะเชื่อมกับระบบสมาชิก ปัจจุบันเตรียมบาร์โค้ดฝั่งสมาชิกและสัญญาการเชื่อมต่อไว้แล้ว ยังไม่มีโปรแกรม POS, ไฟล์ .exe หรือ driver อุปกรณ์ในรุ่นนี้

## ขั้นที่ 1 — บาร์โค้ดสมาชิก (ทำแล้ว)

- สมาชิกกดใช้คูปองเพื่อแสดงบาร์โค้ด CODE128-C เป็นรหัสตัวเลขสุ่ม 32 หลัก
- รหัสไม่บรรจุชื่อ เบอร์โทร เลขสมาชิก หรือยอดส่วนลดที่ POS จะเชื่อถือเอง
- backend เก็บเฉพาะ SHA-256 ของรหัส อายุ 10 นาที หรือจนคูปองหมดอายุ แล้วแต่ว่าอะไรถึงก่อน
- เปิดรหัสใหม่ทำให้รหัสเก่าใช้ไม่ได้ ไม่เก็บรหัสดิบใน localStorage, URL หรือ log
- การเปิด/ปิดบาร์โค้ดไม่ใช่การใช้คูปอง สมาชิกยังไม่มีสิทธิ์ยืนยันการชำระเงิน
- หน้าแสดงบาร์โค้ดตรวจสถานะทุก 5 วินาที เมื่อ backend มี usedAt จากการชำระเงินจริง จึงซ่อนบาร์โค้ดและนำคูปองออกจากรายการ
- ยังไม่มี endpoint สำหรับ POS ตรวจ/จอง/ตัดสิทธิ์จริง และยังไม่มีการตัดสิทธิ์จากการสแกน

## ขั้นที่ 2 — POS คิดเงินและเชื่อมคูปอง (ถัดไป)

1. พนักงานเข้าสู่ระบบ POS ด้วยสิทธิ์ที่ backend อนุญาต แยกจากบัญชีสมาชิก
2. เปิดบิล สแกนบาร์โค้ดจากจอลูกค้า หรือกรอกรหัสผ่านช่องสแกน เครื่องอ่านแบบ keyboard wedge สามารถส่งตัวเลขและ Enter ได้ แต่ต้องทดสอบรุ่นจริง
3. ส่งรหัสให้ backend ผ่าน HTTPS โดยไม่ใส่ใน query string/backend log
4. backend hash รหัสแล้วตรวจคูปอง เจ้าของ วันหมดอายุ สถานะ และเงื่อนไขราคา/ส่วนลดจากฐานข้อมูล ห้ามใช้ยอดที่ frontend ส่งมาเป็นยอดจริง
5. จองคูปองให้บิลนั้นแบบมีเวลาหมดอายุ เพื่อกันอีกบิลนำคูปองเดียวกันมาใช้ระหว่างคิดเงิน การสแกนอย่างเดียวไม่ตั้ง usedAt
6. เมื่อยืนยันรับเงินจริงหรือได้รับผลชำระจากผู้ให้บริการ ให้บันทึก PAID + รายการชำระ + usedAt คูปอง + ยกเลิกบาร์โค้ด + audit log ใน transaction เดียว
7. ใช้ idempotency key ต่อการยืนยันบิล เพื่อให้ retry หลัง Wi-Fi หลุดไม่สร้างบิลหรือหักคูปองซ้ำ
8. ถ้ายกเลิกบิล ชำระไม่สำเร็จ หรือการจองหมดอายุ ให้คืนการจอง คูปองยังไม่ใช้

โครงสร้างที่ต้องเพิ่ม: POS user/device credential, Bill, BillItem, Payment, CouponReservation, บันทึกงานพิมพ์ และข้อมูลร้านสำหรับใบเสร็จ ไม่เปิด API ยืนยันชำระเงินแบบสาธารณะ

ตอนนี้ Campaign มี extraPrice สำหรับค่าเพิ่ม เช่น ทะเล +79 เท่านั้น ก่อนใช้ส่วนลดจริงต้องเพิ่มชนิดสิทธิ์ (ค่าเพิ่ม / ลดจำนวนบาท / ลดเปอร์เซ็นต์) ยอดขั้นต่ำ และวิธีคำนวณที่ backend ให้ชัดเจน ห้ามนำ extraPrice ไปหักยอดโดยอัตโนมัติ

## ขั้นที่ 3 — ติดตั้งและอุปกรณ์

- เป้าหมาย .exe ใช้กับ Windows ต้องยืนยัน OS และสถาปัตยกรรมแท็บเล็ตก่อน หากเป็น Android จะต้องใช้รูปแบบแอปต่างออกไป
- ยังไม่เลือก library/driver Bluetooth หรือคำสั่งเปิดลิ้นชัก จนทราบรุ่นและวิธีเชื่อมต่อของเครื่องพิมพ์
- ตรวจว่าเครื่องพิมพ์รองรับคำสั่งเปิดลิ้นชักที่ต่อกับพอร์ตของมัน และสาย/แรงดันตรงกับลิ้นชักจริง
- ให้คำสั่งพิมพ์และเปิดลิ้นชักอยู่ในตัวแอปบนเครื่อง ไม่เปิดสิทธิ์ฮาร์ดแวร์ให้เว็บสมาชิก
- เปิดลิ้นชักตามประเภทชำระและสิทธิ์พนักงาน บันทึกเหตุการณ์ทุกครั้ง
- บันทึกบิลสำเร็จก่อนสั่งพิมพ์ หากพิมพ์ล้มเหลวให้พิมพ์ซ้ำจากบิลเดิม ไม่คืนคูปองหรือสร้างรายการชำระซ้ำ
- ใช้ Wi-Fi เพื่อซิงก์ข้อมูล ส่วนใช้คูปองต้องตรวจออนไลน์จนกว่าจะออกแบบ offline reconciliation โดยเฉพาะ

## ข้อมูลที่ต้องทราบก่อนทำฮาร์ดแวร์

OS แท็บเล็ตและรุ่น, รุ่นเครื่องพิมพ์, ความกว้างกระดาษ, วิธีเชื่อมต่อ Bluetooth/USB/LAN, รุ่นลิ้นชักและสายเชื่อม, รุ่นเครื่องสแกน, ข้อมูลร้านและรูปแบบใบเสร็จ, ประเภทชำระที่จะรองรับ
