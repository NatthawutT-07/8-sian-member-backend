# สะสมจำนวนครั้งที่มาทาน

รุ่นนี้ยังไม่มี POS ออกใบเสร็จ จึงใช้เจ้าหน้าที่/แอดมินยืนยันการชำระเงินและเลขใบเสร็จจริงหลังออกใบเสร็จ ระบบนับ 1 ใบเสร็จ = 1 ครั้ง ไม่คำนวณแต้มตามยอดเงิน และยังไม่แลกคะแนนอัตโนมัติ

## ลูกค้า

1. เข้าสู่ระบบด้วย LINE แล้วกด **สะสมครั้ง** บนบัตรสมาชิก
2. หากยังไม่มีเบอร์ ให้เพิ่มเบอร์มือถือไทย 10 หลักครั้งเดียว เบอร์ต้องไม่ซ้ำกับสมาชิกอื่น ระบบนี้ไม่ได้ยืนยันเบอร์ด้วย OTP และไม่ใช้การกรอกเบอร์เพื่อย้ายคูปองหรือครอบครองบัญชีอื่น
3. แสดง QR หรือแจ้งเบอร์โทร/เลขสมาชิกให้ร้าน
4. จำนวนครั้งแสดงบนบัตร เปิด QR อยู่จะตรวจยอดทุก 5 วินาที หรือกลับมาโฟกัสหน้าสมาชิกเพื่อตรวจยอดล่าสุด

QR สมาชิกกับ QR คูปองเป็นคนละรหัส QR สมาชิกใช้ prefix `8SM-` ตามด้วย token สุ่ม ไม่มีเบอร์โทรหรือ LINE user ID อยู่ในรหัส เก็บเพียง hash ในฐานข้อมูล อายุ 10 นาที เปิดใหม่ทำให้รหัสเดิมใช้ไม่ได้ การสแกนไม่ได้เพิ่มครั้งและใช้ล็อกอินไม่ได้

## เจ้าหน้าที่

1. เข้าหน้าแอดมิน → **สะสมครั้ง**
2. คลิกช่องค้นหา แล้วใช้เครื่องสแกน QR แบบส่งข้อความเข้าช่อง input (keyboard wedge) หรือพิมพ์เบอร์โทร/เลขสมาชิก เช่น `8S-000001` แล้วค้นหา ไม่ได้เปิดกล้องจากเว็บในรุ่นนี้
3. ตรวจชื่อและเบอร์สมาชิกให้ถูกต้อง
4. หลังชำระเงินและออกใบเสร็จแล้ว กรอกเลขใบเสร็จเต็ม เช่น `20261027-001` หรือ `BRANCH01-20261027-001` ต้องเป็นเลขที่ไม่ซ้ำทั้งร้าน ไม่ใช้เฉพาะเลขลำดับที่วนซ้ำทุกวัน
5. ติ๊ก **ชำระเงินและออกใบเสร็จแล้ว** แล้วกด **เพิ่ม 1 ครั้ง**

ใบเสร็จเดียวกันส่งซ้ำให้สมาชิกคนเดิมจะไม่เพิ่มซ้ำ ถ้าส่งใบเสร็จเดิมให้คนอื่นจะถูกปฏิเสธ ทุกการเพิ่มครั้งมี audit log และ transaction การสแกน/ค้นหาหรือการกรอกเบอร์ไม่เพิ่มครั้งเอง

## API

ใช้ session cookie และ Origin guard เดิม ไม่ใส่ token ใน query string

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| GET `/api/members/me/loyalty` | สมาชิก | เบอร์, จำนวนครั้ง, 10 รายการล่าสุดของตัวเอง |
| POST `/api/members/me/phone` | สมาชิก | `{ phone }` เพิ่มเบอร์เมื่อยังไม่มี ไม่เปลี่ยนเบอร์ที่มีแล้ว |
| POST `/api/members/me/loyalty-code` | สมาชิก | ออก QR อายุ 10 นาที ต้องมีเบอร์ก่อน |
| POST `/api/admin/loyalty/lookup` | แอดมิน | `{ query }` ค้นด้วย QR / เบอร์โทร / เลขสมาชิก |
| POST `/api/admin/loyalty/visits` | แอดมิน | `{ memberId, receiptNumber, receiptIssued: true }` เพิ่ม 1 ครั้งแบบกันซ้ำ |

จำนวนครั้งได้จาก count ของแถว DiningVisit ไม่รับค่า points/ยอดครั้งที่ frontend ส่งมา เลขใบเสร็จ normalize เป็นตัวพิมพ์ใหญ่และห้ามมีช่องว่าง เบอร์ไม่ซ้ำและต้องเพิ่มผ่านบัญชีสมาชิกที่ล็อกอินอยู่

## Deploy

มี migration `202610270003_dining_visits` เพิ่ม DiningVisit และช่อง QR hash/expiry บน Member สำรองฐานข้อมูลก่อน deploy แล้วใน backend repository รัน:

```sh
npm ci
npm run generate
npm run migrate
pm2 restart 8sian-backend --update-env
```

Deploy backend ก่อน frontend ไม่ต้องเพิ่ม environment variable ใหม่ และไม่ต้องแก้ LINE Developers ทดสอบเพิ่มเบอร์/ค้นสมาชิก/ยืนยันใบเสร็จ/ลองซ้ำก่อนใช้งานจริง

## เชื่อม POS ภายหลัง

ส่ง event เมื่อบิลถูกบันทึกเป็นชำระแล้วและมีเลขใบเสร็จถาวร โดยใช้ credential ฝั่ง POS ที่จำกัดสิทธิ์ และใช้เลขใบเสร็จเดียวกับระบบนี้เป็น idempotency key การพิมพ์ซ้ำหรือ retry หลังเน็ตหลุดต้องไม่สร้างครั้งใหม่

ยังไม่มี POS callback หรือ service credential ในรุ่นนี้ ไม่ให้ลูกค้าเรียก API เพิ่มครั้ง และไม่ใช้การกดปุ่มหน้าสมาชิกเป็นหลักฐานออกใบเสร็จ หากต้องรองรับยกเลิก/คืนเงิน ต้องออกแบบรายการย้อนกลับพร้อมเหตุผลและ audit ก่อนเปิดใช้งานใน POS
